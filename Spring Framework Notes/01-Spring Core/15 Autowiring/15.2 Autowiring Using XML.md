# 🌱 Autowiring Using XML 


> **Goal:** Learn how to perform **Autowiring using XML configuration** in Spring Framework.

This topic is extremely important because it helps you understand how Spring performs dependency injection **before moving to annotation-based autowiring (`@Autowired`)**, which is used in Spring Boot.

---

# 📖 1. What is Autowiring Using XML?

Autowiring using XML means:

> Instead of manually writing `<property ref="...">`, we tell Spring to automatically inject the required bean using the `autowire` attribute.

Without Autowiring:

```xml
<bean id="engine" class="com.springcore.autowire.Engine"/>

<bean id="car" class="com.springcore.autowire.Car">
    <property name="engine" ref="engine"/>
</bean>
```

With Autowiring:

```xml
<bean id="engine" class="com.springcore.autowire.Engine"/>

<bean id="car"
      class="com.springcore.autowire.Car"
      autowire="byName"/>
```

Spring automatically injects the `Engine` bean.

---

Imagine a **Car**.

A Car requires:

Without Autowiring:

```text
Developer manually installs
```

# 📌 3. XML Syntax

```xml
<bean id="beanId"
      class="package.ClassName"
      autowire="TYPE"/>
```

The important attribute is:

```xml
autowire="..."
```

---

# 📖 4. Types of XML Autowiring

Spring supports **five modes**.

|Type|Meaning|
|---|---|
|no|No automatic injection (Default)|
|byName|Inject by bean id/name|
|byType|Inject by bean type/class|
|constructor|Inject using constructor|
|autodetect|Deprecated (Do not use)|

> **For interviews, focus on:** `no`, `byName`, `byType`, and `constructor`.

# 🔹 Type 1: `autowire="no"`

## What is it?

This is the **default mode**.

Spring **does not inject anything automatically**.

You must manually specify dependencies.

---

### Example

```xml
<bean id="engine"
      class="com.springcore.autowire.Engine"/>

<bean id="car"
      class="com.springcore.autowire.Car">

    <property name="engine" ref="engine"/>

</bean>
```

This is exactly what you've been doing so far.

---

### Flow

```text
Developer
      │
      ▼
Writes property ref
      │
      ▼
Spring Injects Bean
```

---

# 🔹 Type 2: `autowire="byName"`

This is the **first real autowiring mode**.

Spring matches:

> **Property name = Bean id**

Suppose:

```java
private Engine engine;
```

The property name is:

```text
engine
```

Spring searches for:

```xml
id="engine"
```

If found,

Spring injects it.

---

### Rule

```text
Property Name

=

Bean ID
```

Both names must match exactly.

---

### Example

```java
public class Car {

    private Engine engine;

    public void setEngine(Engine engine) {
        this.engine = engine;
    }
}
```

XML

```xml
<bean id="engine"
      class="com.springcore.autowire.Engine"/>

<bean id="car"
      class="com.springcore.autowire.Car"
      autowire="byName"/>
```

Spring sees:

```text
Property

engine

↓

Search Bean

engine

↓

Found

↓

Inject
```

---

# 🔹 Type 3: `autowire="byType"`

Here Spring ignores the bean name.

It matches by **class type**.

Suppose:

```java
private Engine engine;
```

Spring searches:

```text
Engine class
```

Not

```text
Bean name
```

---

### Rule

```text
Property Type

=

Bean Class
```

---

Example

```xml
<bean id="myEngine"
      class="com.springcore.autowire.Engine"/>

<bean id="car"
      class="com.springcore.autowire.Car"
      autowire="byType"/>
```

Notice:

```text
Bean id

myEngine
```

Property

```text
engine
```

Different names.

Still works because

Spring matches

```text
Engine class
```

---

# 🔹 Type 4: `autowire="constructor"`

Instead of using setter methods,

Spring injects dependencies through the constructor.

Example

```java
public Car(Engine engine) {
    this.engine = engine;
}
```

XML

```xml
<bean id="engine"
      class="com.springcore.autowire.Engine"/>

<bean id="car"
      class="com.springcore.autowire.Car"
      autowire="constructor"/>
```

Spring automatically calls

```java
new Car(engine);
```

---

# 📊 Comparison

|Autowiring Type|Matches By|
|---|---|
|no|Manual configuration|
|byName|Bean ID|
|byType|Bean Class|
|constructor|Constructor parameter|

# ⚠️ Common Mistakes

### ❌ Bean id doesn't match property name (`byName`)

Property:

```java
private Engine engine;
```

Bean:

```xml
id="carEngine"
```

Result:

No injection.

---

### ❌ Multiple beans of the same type (`byType`)

```xml
<bean id="engine1" class="Engine"/>

<bean id="engine2" class="Engine"/>
```

Spring doesn't know which one to inject.

This causes an exception.

---

### ❌ Constructor parameters don't match (`constructor`)

If Spring cannot resolve the constructor arguments, bean creation fails.

# 🎯 Interview Questions

### Q1. What is XML Autowiring?

**Answer:** XML Autowiring is a feature where Spring automatically injects dependencies based on the configured `autowire` mode instead of requiring explicit `<property ref="...">` elements.

---

### Q2. What are the XML autowiring modes?

- `no`
    
- `byName`
    
- `byType`
    
- `constructor`
    
- `autodetect` (deprecated)
    

---

### Q3. Which mode is the default?

**Answer:** `no`

---

### Q4. Which mode uses bean IDs?

**Answer:** `byName`

---

### Q5. Which mode uses class types?

**Answer:** `byType`

---

# 🧠 Memory Trick

Remember **NBC**:

- **N** → `no` → **No automatic injection**
    
- **B** → `byName` → **Bean ID**
    
- **B** → `byType` → **Bean Type**
    
- **C** → `constructor` → **Constructor Injection**
    

---

# 📝 Summary

- XML Autowiring uses the `autowire` attribute on a `<bean>`.
    
- Spring supports four commonly used modes:
    
    - `no`
        
    - `byName`
        
    - `byType`
        
    - `constructor`
        
- `byName` matches the **property name** with the **bean ID**.
    
- `byType` matches the **property type** with the **bean class**.
    
- `constructor` injects dependencies through the constructor.
    
- Understanding XML autowiring makes it much easier to learn annotation-based autowiring (`@Autowired`) in Spring Boot.
