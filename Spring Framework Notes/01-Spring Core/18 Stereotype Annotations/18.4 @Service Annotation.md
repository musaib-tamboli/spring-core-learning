
# 🌱 Stereotype Annotations - Part 4

# `@Service` Annotation

---

# 📖 1. Introduction

## What is `@Service`?

`@Service` is used to mark a class as the **Business Logic Layer** of an application.

It tells Spring:

> **"This class contains business logic. Create and manage it as a Spring Bean."**

---

## Simple Definition

> `@Service` is a specialized `@Component` used for business logic.

---

## Interview Definition

> `@Service` is a stereotype annotation that marks a class as a Service Layer component responsible for implementing business rules and application logic.

---

# 🤔 Why Do We Need `@Service`?

Consider an ATM application.

When a customer withdraws money:

Should the **Controller** calculate the balance?

❌ No.

Should the **Repository** calculate the balance?

❌ No.

The **Service** should perform the business logic.

Example:

```text
Withdraw Money

↓

Check Balance

↓

Check Daily Limit

↓

Deduct Amount

↓

Update Database

↓

Return Success
```

All these rules belong in the **Service Layer**.

---

# 🏦 Real-Life Analogy

Imagine a bank.

```text
Customer

↓

Bank Counter

↓

Bank Manager

↓

Database
```

|Real World|Spring|
|---|---|
|Customer|User|
|Bank Counter|Controller|
|Bank Manager|Service|
|Database Clerk|Repository|

The **manager** makes decisions.

Similarly,

`@Service` contains the application's decision-making logic.

# Step 1 : StudentRepository.java

```java
package com.springcore.stereotype.repository;

import org.springframework.stereotype.Repository;

@Repository
public class StudentRepository {

    public String saveStudent() {

        return "Student Saved Successfully";

    }

}
```

> Don't worry about `@Repository` yet—we'll study it in detail next. For now, just treat it as a bean that handles data access.

---

# Step 2 : StudentService.java

```java
package com.springcore.stereotype.service;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

import com.springcore.stereotype.repository.StudentRepository;

@Service
public class StudentService {

    private final StudentRepository repository;

    @Autowired
    public StudentService(StudentRepository repository) {

        this.repository = repository;

    }

    public void registerStudent() {

        System.out.println("Checking Student Details...");

        System.out.println(repository.saveStudent());

    }

}
```

---

## Explain Every Line

```java
@Service
```

Marks this class as the **Service Layer**.

Spring creates its object automatically.

---

```java
@Autowired
```

Injects the `StudentRepository` bean.

---

```java
repository.saveStudent();
```

Calls the Repository to save data.

# Step 3 : StudentController.java

```java
package com.springcore.stereotype.controller;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;

import com.springcore.stereotype.service.StudentService;

@Component
public class StudentController {

    private final StudentService service;

    @Autowired
    public StudentController(StudentService service) {

        this.service = service;

    }

    public void register() {

        System.out.println("Controller Received Request");

        service.registerStudent();

    }

}
```

For now, we use `@Component`.

Later we'll replace it with `@Controller`.

# Responsibilities

## Controller

Receives requests.

Example:

```text
Register Student
```

---

## Service

Contains business logic.

Example:

```text
Validate Details

↓

Check Rules

↓

Call Repository
```

---

## Repository

Communicates with the database.

---

# Why Not Put Everything in Controller?

Bad Design

```text
Controller

↓

Validation

↓

Business Logic

↓

Database
```

One class does everything.

Very difficult to maintain.

---

# Good Design

```text
Controller

↓

Service

↓

Repository

↓

Database
```

Each layer has one responsibility.

---

# `@Component` vs `@Service`

|@Component|@Service|
|---|---|
|Generic bean|Business logic bean|
|Can be used anywhere|Used only in Service Layer|
|No semantic meaning|Clearly indicates business logic|

Technically both create beans.

The difference is **meaning** and **code organization**.

❌ Writing database code inside Service.

❌ Writing business logic inside Controller.

❌ Using `@Component` everywhere instead of meaningful stereotypes.

# Interview Questions

### Q1. What is `@Service`?

A stereotype annotation used for the business logic layer.

---

### Q2. Is `@Service` different from `@Component` internally?

No.

Internally, `@Service` is a specialized form of `@Component`.

The main difference is semantic meaning.

---

### Q3. What should be written inside a Service class?

- Business rules
    
- Validation
    
- Calculations
    
- Processing
    
- Calls to Repository
    

---

### Q4. Can `@Service` be injected using `@Autowired`?

Yes.

Like any Spring Bean.

---

# 📝 Quick Revision

- ✅ `@Service` is used for the Business Layer.
    
- ✅ It is a specialized `@Component`.
    
- ✅ Spring automatically creates its object.
    
- ✅ It usually communicates with the Repository.
    
- ✅ Controllers should call Services, not Repositories directly.
