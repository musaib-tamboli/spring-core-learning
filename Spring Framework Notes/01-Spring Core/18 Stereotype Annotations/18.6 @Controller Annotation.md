# 📖 1. Introduction

## What is `@Controller`?

`@Controller` is a stereotype annotation used to mark a class as the **Presentation Layer**.

It tells Spring:

> **"This class handles user requests and sends responses."**

---

## Simple Definition

> `@Controller` receives requests from the user and delegates them to the Service layer.

---

## Interview Definition

> `@Controller` is a specialized `@Component` used in Spring MVC to handle HTTP requests and return views or responses.

---

# 🤔 Why Do We Need `@Controller`?

Imagine an Online Shopping Website.

A customer clicks:

```text
Buy Laptop
```

Who receives this request?

Not Service.

Not Repository.

The **Controller** receives it first.

---

# 🏠 Real-Life Analogy

Imagine a restaurant.

```text
Customer

↓

Waiter

↓

Chef

↓

Kitchen
```

Mapping to Spring:

|Restaurant|Spring|
|---|---|
|Customer|User|
|Waiter|Controller|
|Chef|Service|
|Kitchen|Repository/Database|

The waiter **does not cook food**.

He only:

- Takes the order
    
- Gives it to the chef
    
- Brings back the food
    

Similarly, the Controller:

- Receives request
    
- Calls Service
    
- Returns response

# Step 2 : StudentService.java

```java

    @Autowired
    private StudentRepository repository;

    public void registerStudent() {

        System.out.println("Validating Student Details...");

        repository.save(new Student(1, "Rahul"));

```

---

# Step 3 : StudentController.java

```java
package com.springcore.stereotype.controller;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Controller;

import com.springcore.stereotype.service.StudentService;

@Controller
public class StudentController {

    @Autowired
    private StudentService service;

    public void registerStudent() {

        System.out.println("Request Received");

        service.registerStudent();

        System.out.println("Response Sent");

    }

}
```

# Responsibilities of Each Layer

## Controller

- Receives requests
    
- Calls Service
    
- Returns response
    
- No business logic
    

---

## Service

- Validation
    
- Business Rules
    
- Calculations
    
- Processing
    

---

## Repository

- Save Data
    
- Update Data
    
- Delete Data
    
- Fetch Data
    

---

# ❌ Wrong Design

```text
Controller

↓

Validation

↓

Database

↓

Business Logic
```

Controller is doing everything.

Hard to maintain.

---

# ✅ Correct Design

```text
Controller

↓

Service

↓

Repository

↓

Database
```

Each class has one responsibility.

This follows the **Single Responsibility Principle (SRP)** from SOLID principles.

---

# `@Controller` vs `@Component`

|@Component|@Controller|
|---|---|
|Generic Bean|Web Layer Bean|
|Any Layer|Presentation Layer|
|General Purpose|Handles Requests|

Internally both are Spring Beans.

---

# `@Controller` vs `@RestController`

|@Controller|@RestController|
|---|---|
|Returns View (JSP, Thymeleaf, HTML)|Returns JSON/XML|
|Used in MVC Applications|Used in REST APIs|
|Usually works with `Model`|Usually works with `@ResponseBody` automatically|

Example:

```java
@Controller
public class HomeController {

}
```

Example:

```java
@RestController
public class StudentController {

}
```

> **Important:** In Spring Boot, you'll use **`@RestController` much more frequently** than `@Controller` because modern applications commonly expose REST APIs.

# Common Mistakes

## ❌ Writing SQL inside Controller

Wrong

```java
@Controller
public class StudentController {

    public void save() {

        // SQL Query

    }

}
```

---

## ❌ Business Logic inside Controller

Wrong

```java
if (marks > 40) {

}
```

Business logic belongs in the Service layer.

---

## ❌ Calling Repository Directly

Wrong

```text
Controller

↓

Repository
```

Correct

```text
Controller

↓

Service

↓

Repository
```

# Interview Questions

### Q1. What is `@Controller`?

A stereotype annotation used to handle user requests in Spring MVC.

---

### Q2. Is `@Controller` a Spring Bean?

Yes.

It is a specialized `@Component`.

---

### Q3. What is the responsibility of the Controller?

- Receive requests
    
- Delegate work to Service
    
- Return responses
    

---

### Q4. What is the difference between `@Controller` and `@RestController`?

`@Controller` is used for MVC views.

`@RestController` is used for REST APIs and returns response bodies directly.

---

### Q5. Should business logic be written inside Controller?

No.

Business logic belongs in the Service layer.

---
