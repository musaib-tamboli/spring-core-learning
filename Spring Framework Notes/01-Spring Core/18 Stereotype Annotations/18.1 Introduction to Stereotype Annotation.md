# 🌱 Part 1: Introduction to Stereotype Annotations

## 📖 What are Stereotype Annotations?

A **Stereotype Annotation** is a special annotation that tells Spring:

> **"Create an object of this class and manage it as a Spring Bean."**

Instead of writing:

```java
@Bean
public Student student() {
    return new Student();
}
```

You simply write:

```java
@Component
public class Student {
}
```

Spring automatically creates the object.

---

# 🤔 Why Were They Introduced?

Before stereotype annotations:

```
Every class

↓

Need @Bean method

↓

Large Configuration Class

↓

Difficult to Maintain
```

Example:

```java
@Bean
public Student student() { ... }

@Bean
public Teacher teacher() { ... }

@Bean
public Course course() { ... }

@Bean
public Library library() { ... }

// Imagine 500 such methods!
```

This becomes hard to maintain.

Instead:

```java
@Component
public class Student {
}

@Component
public class Teacher {
}

@Component
public class Course {
}
```

Spring finds them automatically.

---

# 🏠 Real-Life Analogy

Imagine a college.

### Without Stereotype Annotations

Principal has to appoint every teacher manually.

```
Teacher A

↓

Teacher B

↓

Teacher C

↓

Teacher D
```

---

### With Stereotype Annotations

Principal announces:

> "Every teacher, report to the staff room."

Everyone comes automatically.

Exactly like:

```java
@ComponentScan
```

# 🎯 Types of Stereotype Annotations

There are **four main stereotype annotations**.

```
          @Component
               │
     ┌─────────┼─────────┐
     │         │         │
@Service  @Repository  @Controller
```

Notice:

All four create Spring Beans.

The difference is **their purpose**.

---

# What is the Difference?

|Annotation|Used For|Layer|
|---|---|---|
|`@Component`|General-purpose bean|Any Layer|
|`@Service`|Business Logic|Service Layer|
|`@Repository`|Database Operations|Repository Layer|
|`@Controller`|Handle HTTP/Web Requests|Controller Layer|

# Why Not Use `@Component` Everywhere?

Technically, you **can** use `@Component` everywhere because:

- `@Service`
    
- `@Repository`
    
- `@Controller`
    

are all specialized forms of `@Component`.

However, using specific annotations makes the code easier to understand.

Example:

```java
@Service
public class PaymentService {
}
```

Immediately tells another developer:

> "This class contains business logic."

---

# Interview Question

### Q: What is the difference between `@Component` and `@Service`?

**Answer:**

Technically, both register a Spring Bean.

The difference is semantic (meaning):

- `@Component` → Generic bean.
    
- `@Service` → Business logic.
    
- `@Repository` → Data access layer.
    
- `@Controller` → Handles web requests.
