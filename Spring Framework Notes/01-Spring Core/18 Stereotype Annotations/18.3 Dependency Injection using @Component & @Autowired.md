# Step 1 : CPU.java

```java
package com.springcore.stereotype;

import org.springframework.stereotype.Component;

@Component
public class CPU {

    public CPU() {
        System.out.println("CPU Bean Created");
    }

    public void process() {
        System.out.println("CPU is Processing...");
    }
}
```

---

# Step 2 : Computer.java (Constructor Injection)

```java
package com.springcore.stereotype;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;

@Component
public class Computer {

    private CPU cpu;

    @Autowired
    public Computer(CPU cpu) {

        this.cpu = cpu;

        System.out.println("Computer Bean Created");
    }

    public void start() {

        System.out.println("Computer Started");

        cpu.process();

    }

}
```

# Behind the Scenes

When Spring sees:

```java
@Autowired
public Computer(CPU cpu)
```

It thinks:

```text
Computer needs a CPU.

↓

Search CPU Bean.

↓

Found.

↓

Pass CPU into Constructor.
```

Equivalent Java code:

```java
CPU cpu = new CPU();

Computer computer = new Computer(cpu);
```

Spring writes this code internally for you.

# How Does Spring Know Which CPU?

Spring looks at the constructor parameter.

```java
public Computer(CPU cpu)
```

It checks:

> "Is there a bean of type `CPU`?"

Yes.

Inject it.

# What If CPU Bean Doesn't Exist?

Suppose:

```java
@Component

    @Autowired

}
```

But

```java
CPU.java
```

has **no `@Component`**.

Output:

```text
NoSuchBeanDefinitionException
```

Because Spring cannot find a `CPU` bean.

# Field Injection

```java
@Component
public class Computer {

    @Autowired
    private CPU cpu;

}
```

Spring injects directly into the field.

Easy to write.

But **not recommended**.

---

# Constructor vs Setter vs Field

|Constructor|Setter|Field|
|---|---|---|
|Mandatory dependency|Optional dependency|Easy but not recommended|
|Immutable object|Mutable object|Hard to test|
|Best Practice ✅|Good|Avoid in production|

# Common Mistakes

## ❌ Forgetting `@Component`

```java
public class CPU {
}
```

Spring never creates the bean.

---

## ❌ Multiple Beans of Same Type

```java
@Component
class IntelCPU {}

@Component
class AMDCPU {}
```

Now Spring gets confused.

Output:

```text
NoUniqueBeanDefinitionException
```

Solution:

```java
@Qualifier("intelCPU")
```

or

```java
@Primary
```

---

## ❌ Using Field Injection Everywhere

Avoid:

```java
@Autowired
private CPU cpu;
```

Prefer:

```java
@Autowired
public Computer(CPU cpu)
```

---
- **What is it?** `@Autowired` is an annotation in the Spring Framework used for **Automatic Dependency Injection**. It tells the Spring IoC (Inversion of Control) container to automatically resolve and inject dependent beans into your target class.
    
- **Why was it introduced?** Before `@Autowired`, developers had to manually wire dependencies together inside XML configuration files using `<property ref="..."/>` or `<constructor-arg ref="..."/>`. This created huge XML files that were tedious to write and hard to maintain. `@Autowired` was introduced to automate this bean-wiring process directly inside Java code.
    
- **What problem does it solve?** It solves **Manual Bean Wiring Overhead**. You no longer need to write `new DependentClass()` manually or wire objects in XML. Spring automatically finds the matching bean in its container memory and hands it to your class.
    
- **Why do companies use it?** Enterprise applications consist of hundreds or thousands of classes working together. `@Autowired` eliminates boilerplate setup code, reduces developer error, accelerates development speed, and makes dependencies clear and easy to manage.

# Interview Questions

### Q1. What is `@Autowired`?

It tells Spring to automatically inject a matching bean into a class.

---

### Q2. How does Spring resolve dependencies?

By searching the IoC container for a bean of the required type.

---

### Q3. Which injection type is recommended?

**Constructor Injection.**

---

### Q4. What happens if multiple beans of the same type exist?

Spring throws:

```text
NoUniqueBeanDefinitionException
```

unless you use `@Qualifier` or `@Primary`.

---

### Q5. Is `@Autowired` mandatory on a single constructor?

In modern Spring versions, if a class has **only one constructor**, `@Autowired` is optional because Spring automatically uses it.

Example:

```java
@Component
public class Computer {

    private final CPU cpu;

    public Computer(CPU cpu) {
        this.cpu = cpu;
    }
}
```

# 📝 Quick Revision

- ✅ `@Autowired` performs dependency injection automatically.
    
- ✅ Constructor Injection is the preferred approach.
    
- ✅ Setter Injection is useful for optional dependencies.
    
- ✅ Field Injection works but is discouraged in production code.
    
- ✅ Spring searches the IoC container by type to resolve dependencies.
    
- ✅ `@Qualifier` and `@Primary` resolve ambiguity when multiple beans of the same type exist.
