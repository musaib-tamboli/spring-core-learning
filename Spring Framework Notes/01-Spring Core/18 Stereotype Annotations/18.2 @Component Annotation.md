# 📖 1. What is `@Component`?

`@Component` tells Spring:

> **"Create an object of this class automatically and manage it inside the Spring IoC Container."**

Instead of creating the object manually:

```java
Computer computer = new Computer();
```

Spring creates it for you.

---

# 🏠 Real-Life Analogy

Imagine a company.

Without Spring:

```text
Manager

↓

Hire Employee

↓

Assign ID

↓

Maintain Employee
```

Everything is done manually.

With Spring:

```text
HR System

↓

Automatically Registers Employee

↓

Assigns ID

↓

Stores Record
```

Here,

- **Employee = Object**
    
- **HR System = Spring Container**
    
- **Registration = @Component**

# 🤔 Why Do We Need `@Component`?

Without `@Component`:

```java
@Bean
public Computer computer() {
    return new Computer();
}
```

Imagine 100 classes.

You need 100 `@Bean` methods.

Very difficult.

With `@Component`:

```java
@Component
public class Computer {
}
```

Spring automatically creates the bean.

# Step 1 : Computer.java

```java
package com.springcore.stereotype;

import org.springframework.stereotype.Component;

@Component
public class Computer {

    public Computer() {
        System.out.println("Computer Bean Created");
    }

    public void start() {
        System.out.println("Computer Started...");
    }

}
```

# 🔍 How Does Spring Find `@Component`?

Spring uses `@ComponentScan`.

```java
@ComponentScan("com.springcore.stereotype")
```

It scans every class inside the package.

For each class:

```text
Computer.java

↓

Is @Component Present?

↓

YES

↓

Create Bean
```

If

```java
@Component
```

is missing

↓

Spring ignores the class.

# 🎯 Default Bean Name

Suppose

```java
@Component

}
```

Bean Name becomes

```text
computer
```

(Class name with lowercase first letter.)

---

# Custom Bean Name

```java
@Component("myComputer")
public class Computer {
}
```

Now

```java
Computer c = context.getBean("myComputer", Computer.class);
```

---

# Difference Between Java Object & Spring Bean

## Normal Java

```java
Computer c = new Computer();
```

You manage the object.

---

## Spring Bean

```java
Computer c = context.getBean(Computer.class);
```

Spring manages the object.

---

# `@Bean` vs `@Component`

|@Bean|@Component|
|---|---|
|Applied on method|Applied on class|
|Manual bean creation|Automatic bean creation|
|Used in `@Configuration`|Used directly on class|
|Best for third-party classes|Best for your own classes|

# Common Mistakes

## ❌ Forgetting `@Component`

```java
public class Computer {
}
```

Output

```text
NoSuchBeanDefinitionException
```

Because Spring doesn't know it should create this object.

---

## ❌ Wrong Package

```java
@ComponentScan("com.xyz")
```

Computer is in

```text
com.springcore.stereotype
```

Result

```text
NoSuchBeanDefinitionException
```

---

## ❌ Using `new`

Wrong

```java
Computer c = new Computer();
```

Correct

```java
Computer c = context.getBean(Computer.class);
```

# 🎤 Interview Questions

### Q1. What is `@Component`?

A class-level annotation that marks a class as a Spring-managed bean.

---

### Q2. Who creates the object?

Spring IoC Container.

---

### Q3. What is the default bean name?

Lowercase class name.

Example:

```java
Computer
```

↓

```text
computer
```

---

### Q4. Can we change the bean name?

Yes.

```java
@Component("officeComputer")
```

---

### Q5. Which annotation scans `@Component`?

```java
@ComponentScan
```

---

### Q6. What happens if `@ComponentScan` is missing?

Spring never discovers the class, so no bean is created.

---
