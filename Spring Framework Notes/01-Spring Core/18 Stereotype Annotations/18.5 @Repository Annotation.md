# 📖 1. Introduction

## What is `@Repository`?

`@Repository` is a stereotype annotation used to mark a class as the **Data Access Layer (DAO)**.

It tells Spring:

> **"This class is responsible for communicating with the database."**

---

## Simple Definition

> `@Repository` is used for database-related classes.

---

## Interview Definition

> `@Repository` is a specialized `@Component` that marks a class as a Data Access Object (DAO) and enables automatic exception translation.

---

# 🤔 Why Do We Need `@Repository`?

Imagine a College Management System.

When a student registers:

```text
Student Registers

↓

Save Student

↓

Database
```

Who should save the student?

❌ Controller?

No.

❌ Service?

No.

✅ Repository.

---

# 🏠 Real-Life Analogy

Imagine a library.

```text
Student

↓

Librarian

↓

Book Record Room
```

Who brings the book?

The librarian.

Similarly,

```text
Application

↓

Repository

↓

Database
```

The Repository acts as the **middleman** between your application and the database.

---

# Responsibilities of Repository

Repository performs operations like:

- Insert Data
    
- Update Data
    
- Delete Data
    
- Search Data
    
- Fetch Data
    

It should **only** contain data access code.


# Step 3 : StudentService.java

```java
package com.springcore.stereotype.service;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

import com.springcore.stereotype.entity.Student;
import com.springcore.stereotype.repository.StudentRepository;

@Service
public class StudentService {

    private final StudentRepository repository;

    @Autowired
    public StudentService(StudentRepository repository) {

        this.repository = repository;

    }

    public void registerStudent() {

        Student student = new Student(1, "Rahul");

        repository.save(student);

    }

}
```

---

# Step 4 : StudentController.java

```java
package com.springcore.stereotype.controller;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;

import com.springcore.stereotype.service.StudentService;

@Component
public class StudentController {

    private final StudentService service;

    @Autowired
    public StudentController(StudentService service) {

        this.service = service;

    }

    public void register() {

        System.out.println("Registration Request Received");

        service.registerStudent();

    }

}
```

# Why Not Use `@Component`?

Technically,

This works.

```java
@Component
public class StudentRepository {

}
```

But

Spring provides

```java
@Repository
```

because it has an additional feature.

---

# The Real Difference

This is the **actual interview answer**.

`@Repository`

↓

Automatically converts low-level database exceptions into Spring's `DataAccessException` hierarchy.

This feature is called **Exception Translation**.

---

## What is Exception Translation?

Imagine your database throws:

```text
SQLException
```

Spring converts it into:

```text
DataAccessException
```

This gives your application a **consistent exception model** regardless of the underlying database technology.

---

# Internal Working

```text
Repository Method

↓

SQLException

↓

@Repository

↓

PersistenceExceptionTranslationPostProcessor

↓

DataAccessException
```

You don't have to catch different database-specific exceptions everywhere.

---

# `@Component` vs `@Repository`

|@Component|@Repository|
|---|---|
|Generic Bean|Database Bean|
|No exception translation|Supports exception translation|
|Can be used anywhere|Used only for data access layer|
|General purpose|DAO layer|

# Interview Questions

## Q1. What is `@Repository`?

A stereotype annotation used for the Data Access Layer.

---

## Q2. Is `@Repository` different from `@Component`?

Yes.

Both create Beans,

but `@Repository` also enables **exception translation** for persistence exceptions.

---

## Q3. Where should database code be written?

Inside Repository classes.

---

## Q4. Which annotation should DAO classes use?

```java
@Repository
```

---

## Q5. What is Exception Translation?

It converts low-level persistence exceptions (such as `SQLException`) into Spring's unified `DataAccessException` hierarchy.

---

# Best Practices

✅ One Repository should usually manage one aggregate or entity (e.g., `StudentRepository`, `OrderRepository`).

✅ Keep SQL/JPA queries in Repository.

✅ Keep validation and calculations in Service.

✅ Keep request handling in Controller.
