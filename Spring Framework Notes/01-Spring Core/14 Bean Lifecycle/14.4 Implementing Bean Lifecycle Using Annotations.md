# 🌱 Implementing Bean Lifecycle Using Annotations (Simple Mobile Example)

So far you've learned **three ways** to implement the Spring Bean Lifecycle:

|Method|How it Works|
|---|---|
|XML|`init-method` and `destroy-method`|
|Interfaces|`InitializingBean` and `DisposableBean`|
|**Annotations** ⭐|`@PostConstruct` and `@PreDestroy`|

> ⭐ **Annotation-based lifecycle** is the **most commonly used approach in modern Spring Boot applications**.

---

# 📖 1. What is Annotation-Based Lifecycle?

Instead of configuring lifecycle methods in XML or implementing Spring interfaces, we simply place annotations above methods.

Spring automatically calls these methods at the appropriate time.

- **`@PostConstruct`** → Called after bean creation and dependency injection.
    
- **`@PreDestroy`** → Called before bean destruction.
    

---

# 🤔 2. Why Use Annotations?

### XML Approach

```xml
<bean id="mobile"
      class="com.springcore.lifecycle.Mobile"
      init-method="start"
      destroy-method="shutdown"/>
```

You must configure lifecycle methods in XML.

---

### Interface Approach

```java
public class Mobile implements InitializingBean, DisposableBean
```

Your class becomes dependent on Spring interfaces.

---

### Annotation Approach

```java
@PostConstruct
public void start() { }

@PreDestroy
public void shutdown() { }
```

No XML configuration and no Spring lifecycle interfaces.

# 📱 5. Mobile.java

```java
package com.springcore.lifecycle;

import jakarta.annotation.PostConstruct;
import jakarta.annotation.PreDestroy;

public class Mobile {

    private String brand;

    public Mobile() {
        System.out.println("1. Mobile Object Created");
    }

    public void setBrand(String brand) {
        System.out.println("2. Setter Injection Called");
        this.brand = brand;
    }

    @PostConstruct
    public void start() {
        System.out.println("3. Mobile Starting...");
    }

    @PreDestroy
    public void shutdown() {
        System.out.println("5. Mobile Shutting Down...");
    }

    @Override
    public String toString() {
        return "Mobile Brand : " + brand;
    }
}
```

# 📄 6. XML Configuration

Since lifecycle methods are handled by annotations, XML becomes simpler.

```xml
<?xml version="1.0" encoding="UTF-8"?>

<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xmlns:context="http://www.springframework.org/schema/context"
       xsi:schemaLocation="
       http://www.springframework.org/schema/beans
       https://www.springframework.org/schema/beans/spring-beans.xsd
       http://www.springframework.org/schema/context
       https://www.springframework.org/schema/context/spring-context.xsd">

    <!-- Enables annotation support -->
    <context:annotation-config/>

    <bean id="mobile"
          class="com.springcore.lifecycle.Mobile">

        <property name="brand" value="Samsung"/>

    </bean>

</beans>
```

> **Important:** `<context:annotation-config/>` enables Spring to process annotations like `@PostConstruct` and `@PreDestroy`.

# ⚙️ 10. Internal Working

Internally, Spring performs something like this:

```java
Mobile mobile = new Mobile();

mobile.setBrand("Samsung");

mobile.start();      // @PostConstruct

// Bean is used

mobile.shutdown();   // @PreDestroy
```

You never call these methods manually—Spring detects the annotations and invokes them.

# 📊 11. Annotation Explanation

|Annotation|Purpose|Called When|
|---|---|---|
|`@PostConstruct`|Initialization|After dependency injection|
|`@PreDestroy`|Cleanup|Before bean destruction|

---

# ⚖️ 12. Comparison of All Three Approaches

|XML|Interface|Annotation|
|---|---|---|
|`init-method`|`afterPropertiesSet()`|`@PostConstruct`|
|`destroy-method`|`destroy()`|`@PreDestroy`|
|XML configuration required|Implements Spring interfaces|Uses annotations|
|Flexible method names|Fixed method names|Flexible method names|
|Older approach|Spring-specific|Modern and preferred|

---

# ✅ Advantages

- Less configuration.
    
- Cleaner and more readable code.
    
- No dependency on Spring lifecycle interfaces.
    
- Widely used in Spring Boot projects.
    

---

# ❌ Disadvantages

- Requires annotation processing to be enabled.
    
- Uses Jakarta annotations, so the dependency must be available.
    

---

# 🎯 Interview Questions

### Q1. Which annotations are used for bean lifecycle?

**Answer:**

- `@PostConstruct`
    
- `@PreDestroy`
    

---

### Q2. When is `@PostConstruct` executed?

**Answer:**

After the bean is created and all dependencies have been injected.

---

### Q3. When is `@PreDestroy` executed?

**Answer:**

Just before the bean is destroyed (typically for singleton beans when the container shuts down).

---

### Q4. Why is `@PostConstruct` preferred over `init-method`?

**Answer:**

It keeps lifecycle configuration close to the code, reducing XML configuration and improving readability.

---

### Q5. Which lifecycle approach is preferred today?

**Answer:**

For modern Spring applications, annotation-based lifecycle methods are generally preferred over XML and Spring-specific lifecycle interfaces.

# 📝 Final Summary

Spring provides **three ways** to implement bean lifecycle methods:

|Approach|Initialization|Cleanup|
|---|---|---|
|XML|`init-method`|`destroy-method`|
|Interfaces|`afterPropertiesSet()`|`destroy()`|
|Annotations ⭐|`@PostConstruct`|`@PreDestroy`|

For new Spring and Spring Boot projects, **annotation-based lifecycle methods** are typically the preferred choice because they are concise, readable, and keep lifecycle logic close to the code.
