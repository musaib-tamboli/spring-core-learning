# 🌱 Spring Bean Scope (Simple & Beginner Friendly)

Bean Scope is one of the **most important Spring Core interview topics**. It decides **how many objects (beans) Spring should create** and **how long they should live**.

---

# 📖 1. What is Bean Scope?

## Simple Definition

**Bean Scope defines the lifecycle and the number of objects Spring creates for a bean.**

### One-Line Definition

> **Bean Scope tells Spring how many instances of a bean should be created and managed.**

### Interview Definition

> **Bean Scope is a configuration that determines the visibility, lifecycle, and number of bean instances managed by the Spring IoC Container.**

---

# 🤔 2. Why Do We Need Bean Scope?

Imagine you have a class:

```java
public class Mobile {
}
```

When Spring reads this bean:

```xml
<bean id="mobile" class="com.springcore.scope.Mobile"/>
```

Questions arise:

- Should Spring create **one object**?
    
- Should Spring create **a new object every time**?
    
- Should all users share the same object?
    

This behaviour is controlled by **Bean Scope**.

---

# 📱 3. Real-Life Analogy

Imagine a **TV Remote**.

### 🏠 House 1 (Singleton)

One TV.

One Remote.

Everyone shares the same remote.

```text
Father
      \
Mother ---> One Remote
      /
Son
```

Only **one remote** exists.

---

### 🏨 Hotel Room (Prototype)

Every room has its own remote.

```text
Room 101 --> Remote 1

Room 102 --> Remote 2

Room 103 --> Remote 3
```

Each request gets a **new remote**.

Spring works exactly the same way.

---

# 📦 4. Types of Bean Scope

Spring provides **6 scopes**.

|Scope|Description|
|---|---|
|Singleton|One object for the entire Spring container|
|Prototype|New object every time requested|
|Request|One object per HTTP request|
|Session|One object per HTTP session|
|Application|One object per ServletContext|
|WebSocket|One object per WebSocket session|

> **For Spring Core**, focus mainly on **Singleton** and **Prototype**. The others are used in web applications.

---

# ⭐ 5. Singleton Scope

## What is Singleton?

Spring creates **only one object**.

Whenever you request the bean, Spring returns the **same object**.

---

### XML Configuration

```xml
<bean id="mobile"
      class="com.springcore.scope.Mobile"
      scope="singleton"/>
```

`singleton` is also the **default scope**, so you can omit it.

---

### Mobile.java

```java
package com.springcore.scope;

public class Mobile {

    public Mobile() {
        System.out.println("Mobile Object Created");
    }
}
```

---

### Test.java

```java
package com.springcore.scope;

import org.springframework.context.ApplicationContext;
import org.springframework.context.support.ClassPathXmlApplicationContext;

public class Test {

    public static void main(String[] args) {

        ApplicationContext context =
                new ClassPathXmlApplicationContext("scopeconfig.xml");

        Mobile m1 = (Mobile) context.getBean("mobile");
        Mobile m2 = (Mobile) context.getBean("mobile");

        System.out.println(m1);
        System.out.println(m2);

        System.out.println(m1 == m2);
    }
}
```

---

### Output

```text
Mobile Object Created

com.springcore.scope.Mobile@45ab

com.springcore.scope.Mobile@45ab

true
```

> **Why `true`?** Because both variables point to the **same object**.

---

# 📊 Memory Diagram (Singleton)

```text
Spring Container
       │
       ▼
   Mobile Object
      @45ab
     /     \
   m1       m2
```

Both references point to the **same instance**.

---

# ⭐ 6. Prototype Scope

## What is Prototype?

Every call to `getBean()` creates a **new object**.

---

### XML Configuration

```xml
<bean id="mobile"
      class="com.springcore.scope.Mobile"
      scope="prototype"/>
```

---

### Test.java

```java
ApplicationContext context =
        new ClassPathXmlApplicationContext("scopeconfig.xml");

Mobile m1 = (Mobile) context.getBean("mobile");
Mobile m2 = (Mobile) context.getBean("mobile");

System.out.println(m1);
System.out.println(m2);

System.out.println(m1 == m2);
```

---

### Output

```text
Mobile Object Created

Mobile Object Created

com.springcore.scope.Mobile@1234

com.springcore.scope.Mobile@9876

false
```

Two objects are created.

---

# 📊 Memory Diagram (Prototype)

```text
Spring Container
      │
      ├────────► Mobile @1234
      │             ▲
      │             │
      │            m1
      │
      └────────► Mobile @9876
                    ▲
                    │
                   m2
```

Each call gets a **new object**.

---

# 🔄 Internal Working

### Singleton

```text
Application Starts
        │
        ▼
Spring Creates One Bean
        │
        ▼
Stores in IoC Container
        │
        ▼
Every getBean()
        │
        ▼
Returns Same Object
```

---

### Prototype

```text
Application Starts
        │
        ▼
No Object Yet
        │
        ▼
getBean()
        │
        ▼
Create New Object
        │
        ▼
Return Object

Next getBean()
        │
        ▼
Create Another Object
```

---

# 📊 Singleton vs Prototype

|Feature|Singleton|Prototype|
|---|---|---|
|Objects Created|One|Many|
|Default Scope|✅ Yes|❌ No|
|Memory Usage|Lower|Higher|
|Performance|Better|Slightly slower|
|Shared|Yes|No|
|Lifecycle Managed by Spring|Full lifecycle|Creation only|

# 🏢 Real-World Examples

### Singleton

Use when all users can share the same object.

Examples:

- Database Connection Pool
    
- Configuration Class
    
- Logging Service
    
- Cache Manager
    

---

### Prototype

Use when every user needs a separate object.

Examples:

- Shopping Cart
    
- Invoice
    
- Report Generator
    
- File Upload Object
    

---

# ⚠️ Common Mistakes

### ❌ Mistake 1

Thinking Spring always creates a new object.

**Wrong.**

By default, Spring uses **Singleton**.

---

### ❌ Mistake 2

Expecting `destroy-method` to run automatically for Prototype beans.

It does **not**.

---

### ❌ Mistake 3

Using Prototype unnecessarily.

Creating many objects increases memory usage.

---

# 🎯 Interview Questions

### Q1. What is Bean Scope?

**Answer:** Bean Scope defines how many instances of a bean Spring creates and manages.

---

### Q2. What is the default scope in Spring?

**Answer:** Singleton.

---

### Q3. Which scope creates a new object every time?

**Answer:** Prototype.

---

### Q4. Which scope is memory efficient?

**Answer:** Singleton.

---

### Q5. Which scope is suitable for a shopping cart?

**Answer:** Prototype, because each user should have a separate cart.

# 🧠 Memory Trick

Remember **SP**:

```text
S → Singleton → Same Object

P → Prototype → Plenty of Objects
```

Or:

```text
Singleton
=
Single Object

Prototype
=
Produce New Object Every Time
```

---

# 📝 Summary

- **Bean Scope** controls how many bean instances Spring creates.
    
- **Singleton** (default): one shared object for the entire container.
    
- **Prototype**: a new object is created every time `getBean()` is called.
    
- In Spring Core, **Singleton** and **Prototype** are the most important scopes to master.
    
- Singleton is ideal for shared services, while Prototype is ideal for stateful or user-specific objects.
