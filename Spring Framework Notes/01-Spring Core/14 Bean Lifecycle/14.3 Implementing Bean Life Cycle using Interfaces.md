# 🚀 1. Introduction

## What is it?

Spring provides two special interfaces:

- **InitializingBean**
    
- **DisposableBean**
    

These interfaces allow a bean (Java object managed by Spring) to execute custom code:

- after the bean is completely created
    
- before the bean is destroyed
    

Simply put,

> They tell Spring,
> 
> **"Call my method when I am ready."**
> 
> **"Call another method before removing me."**

---

## Why was it introduced?

Imagine your application needs to:

- Open a database connection
    
- Load configuration
    
- Read files
    
- Create cache
    
- Start a scheduler
    

These tasks should happen only after Spring has created the object.

Similarly,

Before application shutdown, you may need to:

- Close database connection
    
- Save cache
    
- Stop threads
    
- Release memory
    

Without lifecycle methods, developers had to call these manually.

Spring automated this process.

---

## What problem does it solve?

Without lifecycle support:

```java
Database db = new Database();

db.connect();

// later

db.disconnect();
```

The developer must remember:

- when to initialize
    
- when to destroy
    

If forgotten:

- Memory leak
    
- Resource leak
    
- Connection leak
    
- Application crash
    

Spring solves this automatically.

---

## Why do companies use it?

Large applications have thousands of beans.

Examples:

- Database Connection
    
- Kafka Producer
    
- Redis Client
    
- Email Service
    
- File Reader
    

Each needs initialization and cleanup.

Spring handles it automatically.

---

> [!TIP]  
> Think of lifecycle methods as **automatic startup and shutdown methods**.

---

### 🎯 Interview Question

> **Why do we need Bean Lifecycle methods?**

**Answer:**

To execute custom initialization and cleanup logic automatically during bean creation and destruction.

# 📘 3. Definition

## Simple Definition

InitializingBean and DisposableBean are Spring interfaces that allow executing code during bean initialization and bean destruction.

---

## Interview Definition

InitializingBean provides the `afterPropertiesSet()` callback invoked after dependency injection.

DisposableBean provides the `destroy()` callback invoked before bean destruction.

---

## One-Line Definition

They are lifecycle callback interfaces provided by Spring.

## Explain Every Keyword

```java
implements
```

Means

"My class promises to implement these interfaces."

---

```java
InitializingBean
```

Spring interface for initialization.

---

```java
DisposableBean
```

Spring interface for destruction.

---

```java
@Override
```

Tells Java we are overriding interface methods.

---

```java
afterPropertiesSet()
```

Runs after all dependencies are injected.

---

```java
destroy()
```

Runs before bean destruction.

---

## Best Practice Syntax

```java
@Component
public class DatabaseService
        implements InitializingBean, DisposableBean {

    @Override
    public void afterPropertiesSet() {

        System.out.println("Opening Database Connection...");
    }

    @Override
    public void destroy() {

        System.out.println("Closing Database Connection...");
    }
}
```

# 🏷️ 11. Important Interfaces

|Interface|Purpose|Called When|
|---|---|---|
|`InitializingBean`|Initialization|After dependency injection|
|`DisposableBean`|Cleanup|Before bean destruction|

---

## When to Use

✅ Database connection

✅ Cache loading

✅ File loading

✅ Scheduler

✅ Email server

---

## When NOT to Use

❌ Simple POJO with no initialization logic

❌ Stateless utility classes

---

> [!IMPORTANT]  
> Modern Spring projects usually prefer **`@PostConstruct`** and **`@PreDestroy`** (or custom `initMethod`/`destroyMethod`) because they reduce coupling to Spring-specific interfaces. However, `InitializingBean` and `DisposableBean` are still important for understanding the framework and may appear in interviews or legacy projects.

---

# ✅ 12. Advantages

- Automatic initialization
    
- Automatic cleanup
    
- Less manual code
    
- Prevents resource leaks
    
- Better lifecycle management
    
- Easy to understand
    
- Managed entirely by Spring
    

---

# ❌ 13. Disadvantages

- Couples your class to the Spring Framework (your class directly depends on Spring interfaces).
    
- Makes the code less reusable outside Spring.
    
- Modern projects often prefer annotations (`@PostConstruct`, `@PreDestroy`) for cleaner code.
    

---

# ⭐ 14. Features

|Feature|Explanation|
|---|---|
|Automatic Callback|Spring invokes the methods automatically.|
|Lifecycle Management|Runs code at startup and shutdown.|
|Resource Management|Initialize and release resources safely.|
|Dependency-Aware|`afterPropertiesSet()` is called only after dependencies are injected.|

# 📝 Quick Revision Checklist

-  A Spring bean has a lifecycle from creation to destruction.
    
-  `InitializingBean` provides the `afterPropertiesSet()` callback.
    
-  `DisposableBean` provides the `destroy()` callback.
    
-  `afterPropertiesSet()` executes after dependency injection.
    
-  `destroy()` executes before bean destruction.
    
-  These interfaces are useful for initialization and cleanup logic.
    
-  Modern Spring often prefers `@PostConstruct` and `@PreDestroy`, but knowing these interfaces is valuable for interviews and legacy applications.
    

---

> [!TIP]  
> **Memory Trick:** Think **A → D**
> 
> - **A** = **After** properties set → `afterPropertiesSet()`
>     
> - **D** = **Destroy** before bean removal → `destroy()`
>
