# 📖 1. Introduction

## What is Java Configuration?

**Java Configuration** means configuring Spring beans using **Java classes and annotations** instead of XML files.

Instead of writing:

```xml
<bean id="student"
      class="com.spring.Student"/>
```

We write Java code.

```java
@Configuration
public class AppConfig {

    @Bean
    public Student student() {
        return new Student();
    }

}
```

Spring creates the bean exactly the same way.

---

## Why was Java Configuration introduced?

Early versions of Spring used XML.

Large projects had XML files like:

```text
beans.xml

500 Lines

↓

service.xml

800 Lines

↓

dao.xml

600 Lines

↓

controller.xml

700 Lines
```

Problems:

- Huge XML files
    
- Difficult to maintain
    
- No compile-time checking
    
- Typing mistakes were common
    
- Difficult navigation
    

Spring introduced Java Configuration to solve these issues.

# Simple Definition

> Java Configuration is a way of configuring the Spring IoC Container using Java classes instead of XML.

---

# Interview Definition

> Java Configuration is an annotation-based configuration approach where Java classes define Spring beans using `@Configuration` and `@Bean`.

# Main Annotations

There are **three** annotations you must master.

```text
Java Configuration
        │
        ├──────────────┐
        │              │
@Configuration   @ComponentScan
        │
        ▼
      @Bean
```

---

## 1. `@Configuration`

Marks a Java class as a Spring Configuration class.

Equivalent to:

```xml
beans.xml
```

---

## 2. `@Bean`

Creates a Spring Bean.

Equivalent to:

```xml
<bean>
```

---

## 3. `@ComponentScan`

Tells Spring

> Scan this package for components.

Equivalent to:

```xml
<context:component-scan>
```

---

# Comparison

|XML|Java Configuration|
|---|---|
|`<beans>`|`@Configuration`|
|`<bean>`|`@Bean`|
|`<context:component-scan>`|`@ComponentScan`|
