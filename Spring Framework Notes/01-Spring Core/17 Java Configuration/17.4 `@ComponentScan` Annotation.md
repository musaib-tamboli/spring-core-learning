# 📖 1. Introduction

## What is `@ComponentScan`?

`@ComponentScan` tells the Spring Container:

> **"Go to this package and automatically find all Spring Components."**

Instead of manually creating every bean using `@Bean`, Spring automatically scans packages and creates objects for classes annotated with:

- `@Component`
    
- `@Service`
    
- `@Repository`
    
- `@Controller`
    

---

## Simple Definition

> `@ComponentScan` is used to automatically scan packages and register Spring Beans.

---

## Interview Definition

> `@ComponentScan` is a class-level annotation that instructs the Spring IoC Container to scan specified packages for Spring-managed components.

---

# 🤔 Why Do We Need `@ComponentScan`?

Suppose your project contains **100 classes**.

Without `@ComponentScan`, you must create every bean manually.

```java
@Bean
public Student student() {
    return new Student();
}

@Bean
public Teacher teacher() {
    return new Teacher();
}

@Bean
public Course course() {
    return new Course();
}

@Bean
public Library library() {
    return new Library();
}

// Imagine another 96 methods...
```

Very difficult.

Instead, simply write:

```java
@ComponentScan("com.springcore")
```

Spring automatically creates all component beans.

# Difference Between `@Bean` and `@Component`

|`@Bean`|`@Component`|
|---|---|
|Used on methods|Used on classes|
|Object created manually|Object created automatically|
|Inside `@Configuration`|Directly on class|
|Best for third-party classes|Best for your own classes|

---

# When Should You Use `@Bean`?

Use `@Bean` when:

- You cannot modify the source code.
    
- Third-party libraries.
    
- Database configuration.
    
- External APIs.
    
- DataSource configuration.
    

Example:

```java
@Bean
public DataSource dataSource() {
    return new HikariDataSource();
}
```

---

# When Should You Use `@Component`?

Use for classes you create.

Example:

```java
@Component
public class Student {
}
```

---

# How Spring Boot Uses `@ComponentScan`

Suppose your project is:

```text
com.company.project
        │
        ├── controller
        ├── service
        ├── repository
        └── entity
```

Spring Boot automatically scans all sub-packages starting from the package containing the main application class.

```text
@SpringBootApplication

↓

Includes

↓

@ComponentScan

↓

Everything Found Automatically
```

This is why you usually don't write `@ComponentScan` explicitly in Spring Boot.

# Common Mistakes

## ❌ Wrong Package

```java
@ComponentScan("com.xyz")
```

when your classes are in

```text
com.springcore
```

Result:

```
NoSuchBeanDefinitionException
```

---

## ❌ Forgetting `@Component`

```java
public class Student {
}
```

Spring ignores the class.

---

## ❌ Forgetting `@ComponentScan`

Spring never scans the package.

# Interview Questions

### Q1. What is `@ComponentScan`?

It tells Spring to scan packages and automatically register component classes as beans.

---

### Q2. Which annotations are detected?

- `@Component`
    
- `@Service`
    
- `@Repository`
    
- `@Controller`
    

---

### Q3. Does Spring Boot use `@ComponentScan`?

Yes.

`@SpringBootApplication` already includes it.

---

### Q4. What happens if the package name is wrong?

Spring cannot find the classes, leading to bean creation errors.

---

### Q5. Which is better: `@Bean` or `@Component`?

Neither is universally better.

- Use **`@Component`** for your own application classes.
    
- Use **`@Bean`** for third-party or externally configured objects.
    

---

# Best Practices

- ✅ Place the configuration class in a parent package so all sub-packages are scanned.
    
- ✅ Use `@Component` for your own classes.
    
- ✅ Use `@Bean` for third-party classes or complex object creation.
    
- ✅ Keep package structures organised (`controller`, `service`, `repository`, `config`).

- ✔ No need to create beans manually with `@Bean` for your own classes.
