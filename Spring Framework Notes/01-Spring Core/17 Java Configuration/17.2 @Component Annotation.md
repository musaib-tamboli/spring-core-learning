# 📖 1. Introduction

## What is `@Configuration`?

`@Configuration` is an annotation that tells Spring:

> **"This class contains Spring Bean definitions."**

Instead of creating beans inside an XML file, we create them inside a Java class.

---

## Simple Definition

> `@Configuration` marks a Java class as a Spring Configuration Class.

---

## Interview Definition

> `@Configuration` is a Spring annotation used to indicate that a class contains one or more `@Bean` methods, whose returned objects should be managed by the Spring IoC Container.

---

# 🤔 Why Do We Need `@Configuration`?

Before Java Configuration, every bean was declared inside XML.

Example:

```xml
<bean id="student"
      class="com.springcore.javaconfig.Student"/>
```

Large projects contained thousands of XML lines.

Problems:

- Difficult to read
    
- Difficult to maintain
    
- XML syntax errors
    
- Refactoring was hard
    
- No compile-time checking
    

Spring introduced `@Configuration`.

Now everything is Java.

# 📚 What Does `@Configuration` Actually Do?

It tells Spring

```text
This class contains bean creation methods.
```

Spring will scan this class.

Whenever it finds

```java
@Bean
```

it creates that object and stores it inside the IoC Container.

---

# What is `AnnotationConfigApplicationContext`?

Earlier we used

```java
ClassPathXmlApplicationContext
```

because configuration was XML.

Now we use

```java
AnnotationConfigApplicationContext
```

because configuration is Java.

---

# Comparison

| XML Configuration              | Java Configuration                 |
| ------------------------------ | ---------------------------------- |
| ClassPathXmlApplicationContext | AnnotationConfigApplicationContext |
| XML File                       | Configuration Class                |
| `<bean>`                       | `@Bean`                            |
| `<beans>`                      | `@Configuration`                   |

# Important Points

### `@Configuration` itself does **NOT** create beans.

It only tells Spring

```text
Look inside this class.
```

Actual beans are created by

```java
@Bean
```

---

# Common Mistake

Many beginners think

```java
@Configuration
```

creates beans.

It does not.

This alone creates nothing.

```java
@Configuration
public class AppConfig {

}
```

Output

Nothing.

Because no `@Bean` methods exist.

# Interview Questions

## Q1. What is `@Configuration`?

It marks a Java class as a configuration class that contains Spring bean definitions.

---

## Q2. Does `@Configuration` create beans?

No.

It only marks the class.

Beans are created by `@Bean` methods.

---

## Q3. Which ApplicationContext is used with Java Configuration?

```java
AnnotationConfigApplicationContext
```

---

## Q4. Can we use XML and `@Configuration` together?

Yes.

Spring supports both approaches in the same application if needed.

---

# Best Practices

✅ Keep configuration classes focused (e.g., `DatabaseConfig`, `SecurityConfig`).

✅ Use meaningful class names ending with `Config`.

```text
AppConfig
DatabaseConfig
SecurityConfig
WebConfig
```

---

# Quick Revision

- ✅ `@Configuration` replaces the `<beans>` element in XML.
    
- ✅ It marks a class as a Spring configuration class.
    
- ✅ It does **not** create beans by itself.
    
- ✅ `@Bean` methods inside it create the actual beans.
    
- ✅ Use `AnnotationConfigApplicationContext` to load configuration classes.
