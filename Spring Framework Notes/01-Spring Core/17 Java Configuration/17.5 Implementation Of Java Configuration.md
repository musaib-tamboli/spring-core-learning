# Step 3: AppConfig.java

```java
package com.springcore.javaconfig;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class AppConfig {

    @Bean
    public Laptop laptop() {

        return new Laptop();

    }

    @Bean
    public Student student() {

        return new Student(laptop());

    }

}
```

# 🧠 Stop Here...

Many beginners think this happens:

```text
student()

↓

new Student()

↓

laptop()

↓

new Laptop()
```

So every call creates a new Laptop.

**❌ Wrong!**

Spring behaves differently.

# What Actually Happens?

When the container starts:

```
Application Starts
        │
        ▼
Read AppConfig
        │
        ▼
@Configuration Found
        │
        ▼
Find @Bean Methods
```

Spring finds

```
@Bean laptop()

@Bean student()
```

---

## Spring Executes

```
Laptop laptop = laptop();
```

creates

```
Laptop Object
```

stores it.

```
IoC Container

Laptop Bean
```

---

Then

```
Student student = student();
```

Inside

```java
return new Student(laptop());
```

You might think

```
new Laptop()
```

is called again.

### It is NOT.

Spring intercepts the call.

Instead it returns

```
Already Existing Laptop Bean
```

```
AppConfig

      │

      ▼

@Bean laptop()

      │

      ▼

      ▼

      │

      ▼

      │

      ▼
```

# 🤔 Why Doesn't `laptop()` Create a New Object?

Excellent interview question.

Normally

```java
laptop();
```

calls the method.

But because AppConfig has

```java
@Configuration
```

Spring creates a **proxy object** (a special wrapper around the configuration class).

So

```
student()

↓

laptop()

↓

Proxy Checks Container

↓

Already Exists?

↓

Yes

↓

Return Existing Bean
```

Instead of

```
new Laptop()
```

---

# Real Internal Architecture

```
                JVM
                 │
                 ▼
     AnnotationConfigApplicationContext
                 │
                 ▼
        Read AppConfig.class
                 │
                 ▼
     ConfigurationClassPostProcessor
                 │
                 ▼
      Create Proxy of AppConfig
                 │
                 ▼
        Execute @Bean Methods
                 │
                 ▼
        Register Beans
                 │
                 ▼
         IoC Container Ready
```

> **Note:** `ConfigurationClassPostProcessor` is a Spring internal class that processes `@Configuration` classes and enhances them so `@Bean` methods return managed beans instead of creating new objects each time.

---

# Interview Question

**Q:** Why do `@Bean` methods return the same object even when one `@Bean` method calls another?

**Answer:**

Because Spring enhances (`proxies`) the `@Configuration` class. Instead of executing the method directly every time, the proxy first checks the IoC container. If the bean already exists (singleton scope), it returns the existing bean.
