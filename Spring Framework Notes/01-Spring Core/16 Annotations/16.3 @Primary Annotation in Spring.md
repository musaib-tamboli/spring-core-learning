# 📖 1. Introduction

## What is `@Primary`?

`@Primary` is a Spring annotation that tells Spring:

> **"If multiple beans of the same type exist, use this bean as the default."**

Instead of specifying a bean every time using `@Qualifier`, we can make one bean the **default**.

---

## Simple Definition

> `@Primary` marks one bean as the **default bean** for dependency injection.

---

## Interview Definition

> `@Primary` is used to give higher priority to one bean when multiple beans of the same type are present in the Spring IoC Container.

---

# 🤔 Why Do We Need `@Primary`?

Suppose your application has three Engine implementations.

```text
Engine
│
├── PetrolEngine
├── DieselEngine
└── ElectricEngine
```

Every Car uses **PetrolEngine** by default.

Without `@Primary`, every class must write:

```java
@Autowired
@Qualifier("petrolEngine")
private Engine engine;
```

Imagine writing this in **100 classes**.

Not practical.

Instead, mark PetrolEngine as default.

```java
@Primary
@Component
public class PetrolEngine implements Engine
```

Now only:

```java
@Autowired
private Engine engine;
```

Spring automatically injects PetrolEngine.

# Example

---

## Engine.java

```java
package com.springcore.primary;

public interface Engine {

    void start();

}
```

---

## PetrolEngine.java

```java
package com.springcore.primary;

import org.springframework.context.annotation.Primary;
import org.springframework.stereotype.Component;

@Component
@Primary
public class PetrolEngine implements Engine {

    @Override
    public void start() {

        System.out.println("Petrol Engine Started");

    }

}
```

Notice

```java
@Primary
```

This bean becomes the default.

---

## DieselEngine.java

```java
package com.springcore.primary;

import org.springframework.stereotype.Component;

@Component
public class DieselEngine implements Engine {

    @Override
    public void start() {

        System.out.println("Diesel Engine Started");

    }

}
```

---

## Car.java

```java
package com.springcore.primary;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;

@Component
public class Car {

    @Autowired
    private Engine engine;

    public void drive() {

        engine.start();

        System.out.println("Car Running");

    }

}
```

Notice

No

```java
@Qualifier
```

Still works.

Because

```java
@Primary
```

is present.

# What Happens If We Use Both?

Suppose

```java
@Component
@Primary
class PetrolEngine
```

and

```java
@Autowired
@Qualifier("dieselEngine")
private Engine engine;
```

Which one wins?

Answer:

```text
@Qualifier
```

Spring injects

```text
DieselEngine
```

because `@Qualifier` has **higher priority** than `@Primary`.

---

# Priority Order

```text
Highest Priority

@Qualifier

↓

@Primary

↓

@Autowired
```

---

# Comparison

|Feature|@Primary|@Qualifier|
|---|---|---|
|Purpose|Default bean|Specific bean|
|Used When|One implementation should be the default|You need a specific implementation|
|Bean Selection|Automatic|Explicit|
|Priority|Lower|Higher|
|Common Usage|Default service implementation|Special cases|

---

# When to Use `@Primary`

Use `@Primary` when:

- One implementation is used in most places.
    
- You want a default bean.
    
- You want to avoid repeating `@Qualifier` everywhere.
    

Example:

```text
Payment Gateway

UPI

Card

NetBanking
```

Most users use UPI.

Mark:

```java
@Primary
UPIPayment
```

Now all `@Autowired PaymentGateway` injections get `UPIPayment` unless another gateway is explicitly requested.

# Real Project Example

### Banking

```text
NotificationService

↓

EmailNotification   (@Primary)

SMSNotification

PushNotification
```

Most notifications go through Email.

Mark Email as `@Primary`.

If a class specifically needs SMS:

```java
@Autowired
@Qualifier("smsNotification")
```

# Common Mistakes

### ❌ Using Two `@Primary` Beans

```java
@Primary
class PetrolEngine
```

```java
@Primary
class DieselEngine
```

Spring cannot choose.

This results in an error because there are multiple primary candidates.

---

### ❌ Forgetting `@Component`

```java
@Primary
public class PetrolEngine
```

Without

```java
@Component
```

Spring never creates the bean.

# Interview Questions

### Q1. What is `@Primary`?

**Answer:**

It marks one bean as the default choice when multiple beans of the same type exist.

---

### Q2. Can `@Primary` replace `@Qualifier`?

**Answer:**

No.

`@Primary` provides a default bean.

`@Qualifier` selects a specific bean.

---

### Q3. Which has higher priority?

**Answer:**

```text
@Qualifier

>

@Primary
```

---

### Q4. Can multiple beans have `@Primary`?

**Answer:**

No. If more than one bean of the same type is marked `@Primary`, Spring cannot determine the default and bean resolution fails.

```text
      ▼

```

# Summary

- ✅ `@Primary` marks the **default bean**.
    
- ✅ `@Qualifier` selects a **specific bean**.
    
- ✅ `@Qualifier` overrides `@Primary`.
    
- ✅ `@Primary` helps reduce repeated `@Qualifier` annotations.
    
- ✅ Widely used in enterprise Spring Boot applications where one implementation is the standard default.
