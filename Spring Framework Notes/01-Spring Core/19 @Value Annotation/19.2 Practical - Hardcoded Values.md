# Step 1: Mobile.java

```java
package com.springcore.value;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

@Component
public class Mobile {

    @Value("Samsung")
    private String brand;

    @Value("8")
    private int ram;

    @Value("45999.99")
    private double price;

    @Value("true")
    private boolean is5G;

    @Value("A")
    private char grade;

    @Value("123456789012345")
    private long imei;

    public void display() {

        System.out.println("Brand      : " + brand);
        System.out.println("RAM        : " + ram + " GB");
        System.out.println("Price      : ₹" + price);
        System.out.println("5G Support : " + is5G);
        System.out.println("Grade      : " + grade);
        System.out.println("IMEI       : " + imei);

    }
}
```

# Behind the Scenes (Conceptual)

Think of Spring doing something like this:

```java
Mobile mobile = new Mobile();

mobile.brand = "Samsung";
mobile.ram = 8;
mobile.price = 45999.99;
mobile.is5G = true;
mobile.grade = 'A';
mobile.imei = 123456789012345L;
```

You never write this code.

Spring performs it using **reflection** and its type conversion system.

---

# ❓ How does Spring convert `"8"` into `int`?

You wrote:

```java
@Value("8")
private int ram;
```

Notice that `"8"` is a **String** inside the annotation.

Spring internally uses a **Conversion Service** (type conversion mechanism) to convert:

```text
"8"

↓

int 8
```

Similarly,

```text
"true"

↓

boolean true
```

```text
"45999.99"

↓

double 45999.99
```

This automatic conversion is one of Spring's powerful features.

# Common Mistakes

### ❌ Creating object using `new`

```java
Mobile mobile = new Mobile();
```

Output

```text
Brand : null

RAM : 0
```

Because Spring never injected the values.

---

### ✅ Correct

```java
Mobile mobile = context.getBean(Mobile.class);
```

---

### ❌ Forgetting `@Component`

```java
public class Mobile {

}
```

Spring never creates the bean.

`@Value` is ignored.

# Interview Questions

### Q1. Can `@Value` inject primitive types?

✅ Yes.

It supports:

- `int`
    
- `long`
    
- `double`
    
- `float`
    
- `boolean`
    
- `char`
    
- `String`
    

---

### Q2. Does `@Value` only work with Strings?

No.

Although annotation values are written as strings, Spring automatically converts them to the target field type.

---

### Q3. Why does `@Value("8")` work for an `int` field?

Because Spring automatically converts the string `"8"` to the integer `8` using its type conversion mechanism.

---

# 📝 Revision Checklist

-  `@Value` injects simple values into Spring beans.
    
-  The bean must be managed by Spring (`@Component`, `@Service`, etc.).
    
-  Spring automatically converts strings to the required data type.
    
-  Always obtain the bean from the Spring container using `getBean()`.
    
-  Avoid creating the object with `new` when using `@Value`.

# 🎯 Next Part (Most Important)

We'll learn **reading values from external configuration** using:

```properties
mobile.brand=Samsung
mobile.ram=8
mobile.price=45999.99
```

and inject them like this:

```java
@Value("${mobile.brand}")
private String brand;
```

This is the **real-world usage** of `@Value` and is used extensively in **Spring Boot** applications for configurable settings like database URLs, ports, API keys, and feature flags.
