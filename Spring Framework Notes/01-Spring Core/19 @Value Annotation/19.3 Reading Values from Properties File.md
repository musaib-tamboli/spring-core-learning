# 📖 Why Do We Need a Properties File?

Suppose you have this code:

```java
@Component
public class Mobile {

    @Value("Samsung")
    private String brand;

    @Value("8")
    private int ram;

    @Value("45999")
    private double price;
}
```

Tomorrow, the requirements change:

- Brand → Apple
    
- RAM → 12 GB
    
- Price → ₹79,999
    

Without a properties file:

❌ Open Java file

❌ Modify code

❌ Recompile

❌ Redeploy

---

## Better Approach

Keep values outside the Java code.

```
mobile.properties

↓

Spring Reads File

↓

Injects Values

↓

Application Ready
```

Now changing values requires editing only the properties file.

```

The Java code remains unchanged.

package com.springcore.value;

    @Value("${mobile.ram}")

    @Value("${mobile.imei}")

        System.out.println("Grade  : " + grade);
        System.out.println("IMEI   : " + imei);
    }
}
```

# Step 3 : AppConfig.java

Since this is **Spring Core (not Spring Boot)**, we must tell Spring where the properties file is.

```java
package com.springcore.value;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.ComponentScan;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.support.PropertySourcesPlaceholderConfigurer;

@Configuration
@ComponentScan("com.springcore.value")
public class AppConfig {

    @Bean
    public static PropertySourcesPlaceholderConfigurer propertyConfigurer() {
        return new PropertySourcesPlaceholderConfigurer();
    }
}
```

But this is **not enough**.

We also need to tell Spring **which properties file to load**.

---

# Step 4 : Add `@PropertySource`

Update `AppConfig.java`:

```java
package com.springcore.value;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.ComponentScan;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.PropertySource;
import org.springframework.context.support.PropertySourcesPlaceholderConfigurer;

@Configuration
@ComponentScan("com.springcore.value")
@PropertySource("classpath:mobile.properties")
public class AppConfig {

    @Bean
    public static PropertySourcesPlaceholderConfigurer propertyConfigurer() {
        return new PropertySourcesPlaceholderConfigurer();
    }
}
```

---

# What Does `@PropertySource` Do?

```java
@PropertySource("classpath:mobile.properties")
```

Means:

```

↓

↓

Keep values ready

↓

@Value can use them
```

# Spring Core vs Spring Boot

|Spring Core|Spring Boot|
|---|---|
|Need `@PropertySource`|Automatically loads `application.properties`|
|Need `PropertySourcesPlaceholderConfigurer`|Not required|
|Manual configuration|Auto configuration|

This is one of the biggest conveniences provided by Spring Boot.

# Interview Questions

### Q1. Why do we use a properties file?

To keep configuration separate from source code so values can change without modifying Java classes.

---

### Q2. What does `${}` mean in `@Value`?

It tells Spring to look up the value for the specified key from the configured property sources.

---

### Q3. Why do we use `@PropertySource`?

To tell Spring Core which properties file should be loaded.

---

### Q4. Where should a properties file be placed?

In a Maven project:

```
src/main/resources
```
