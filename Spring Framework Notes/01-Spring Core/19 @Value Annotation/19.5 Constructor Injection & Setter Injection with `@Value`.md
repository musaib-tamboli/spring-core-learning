# 📖 Why Learn Different Injection Types?

So far, we've used:

```java
@Component

    @Value("Samsung")
    private String brand;

```

This is called **Field Injection**.

But `@Value` can also be used with:

- ✅ Field Injection
    
- ✅ Constructor Injection
    
- ✅ Setter Injection

# 1️⃣ Field Injection

## Mobile.java

```java
package com.springcore.value;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

@Component
public class Mobile {

    @Value("Samsung")
    private String brand;

    public void display() {
        System.out.println("Brand : " + brand);
    }
}
```

### Internal Working

```text
Spring Creates Object

↓

Find @Value

↓

Inject Samsung

↓

Object Ready
```

---

## Advantages

- Very simple
    
- Less code
    
- Good for learning
    

---

## Disadvantages

- Difficult to test
    
- Cannot create immutable objects
    
- Not preferred in large projects
    

---

# 2️⃣ Constructor Injection

## Mobile.java

```java
package com.springcore.value;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

@Component
public class Mobile {

    private String brand;

    public Mobile(@Value("Samsung") String brand) {

        this.brand = brand;

        System.out.println("Constructor Called");

    }

    public void display() {

        System.out.println("Brand : " + brand);

    }

}
```

---

## Internal Working

Spring performs:

```text
Create Mobile Bean

↓

Read Constructor

↓

Find @Value("Samsung")

↓

Pass Samsung

↓

Call Constructor

↓

Object Ready
```

Conceptually, Spring does something like:

```java
Mobile mobile = new Mobile("Samsung");
```

---

## Output

```text
Constructor Called

Brand : Samsung
```

---

# 3️⃣ Setter Injection

```java
package com.springcore.value;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

@Component
public class Mobile {

    private String brand;

    @Value("Samsung")
    public void setBrand(String brand) {

        this.brand = brand;

        System.out.println("Setter Called");

    }

    public void display() {

        System.out.println("Brand : " + brand);

    }

}
```

---

## Internal Working

```text
Create Object

↓

Call Setter

↓

Pass Samsung

↓

Object Ready
```

Conceptually:

```java
Mobile mobile = new Mobile();

mobile.setBrand("Samsung");
```

---

## Output

```text
Setter Called

Brand : Samsung
```

# 🏢 Which One Do Companies Use?

In real Spring Boot projects:

```java
@Service
public class MobileService {

    private final MobileRepository repository;

    public MobileService(MobileRepository repository) {
        this.repository = repository;
    }
}
```

Constructor Injection is preferred because:

- Dependencies are required when the object is created.
    
- Fields can be `final`.
    
- Easier to unit test.
    
- Prevents partially initialized objects.
    

For simple configuration values (`@Value`), field injection is still common, but constructor injection is also widely used when immutability is desired.

# 📌 Which Should You Use?

## For Learning

Field Injection is easiest.

```java
@Value("Samsung")
private String brand;
```

---

## For Real Projects

Constructor Injection is generally the best choice.

```java
public Mobile(@Value("${mobile.brand}") String brand) {

    this.brand = brand;

}
```

---

## Setter Injection

Use it when the value is optional or may change after object creation.

# ❌ Common Mistakes

### Mistake 1

Forgetting `@Component`

```java
public class Mobile {

}
```

Spring never creates the bean.

---

### Mistake 2

Creating the object manually

```java
Mobile mobile = new Mobile();
```

`@Value` won't work because Spring isn't managing the object.

---

### Mistake 3

Expecting constructor injection without telling Spring what to inject.

```java
public Mobile(String brand) {

}
```

Spring doesn't know where `brand` should come from.

Correct:

```java
public Mobile(@Value("Samsung") String brand) {

}
```

## Q3. Which injection type is recommended?

- **Constructor Injection** → Best for required dependencies.
    
- **Field Injection** → Common for simple configuration values.
    
- **Setter Injection** → Useful for optional values.
    

---

## Q4. Does Spring call the constructor or setter automatically?

Yes. During bean creation, Spring invokes the constructor or setter and supplies the configured value.

- ✅ Setter Injection is useful for optional or changeable values.
    
- ✅ The object must always be managed by Spring.
